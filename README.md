# 商标近似评估智能体（第一轮交付）

申请前筛查：输入中文文字商标和商品，输出候选在先商标、匹配理由和可追溯的风险报告（可导出 Word）。
风险等级由代码按规则表给出，大模型只负责要素解析、解释和措辞。

第一轮范围：申请前筛查全流程，加“用户剔除候选”“模型超时”两条异常路径。驳回复审放在第二步。

## 运行

```bash
conda activate law-agent
pip install -r requirements.txt
cp .env.example .env            # 填 LLM_API_KEY、LLM_MODEL；不填也能跑（走降级路径）
python scripts/import_decisions.py # 决定书 → 真实商标记录与案例库（读 collected/decisions）
python scripts/build_db.py         # 建本地小库（首次会下载 bge-small-zh-v1.5，约 100 MB）
python scripts/build_open_index.py # 为商标开放数据建检索索引（需在 .env 设 TM_OPEN_DB，约 6 分钟）
streamlit run ui/streamlit_app.py
pytest                          # 单元测试与端到端测试，不访问网络
python eval/run_eval.py         # 标识近似评测：指南例子 + 调参集（加 --frozen 评冻结测试集）
```

模型下载不了时：在 `.env` 里设 `HF_ENDPOINT=https://hf-mirror.com`；或 `python scripts/build_db.py --hash`
先用哈希向量应急（商品项映射和义近召回效果会明显变差）。

演示用例见 `eval/demo.yaml`，例如商标“茗悦”、商品“茶饮料、奶茶”。

## 流程（15 个节点，2 个人工挂起点）

`parse` → **确认商品项** → 五路并行召回（精确文字、字形、读音、字序与叠字、含义）→ `merge`（RRF 排名融合）
→ `assess`（规则表定级，不调用模型）→ `explain`（模型解释）→ **确认候选** → `compose`（结构化结论）
→ `verify`（引用校验，失败最多重写 2 次，仍失败则标红输出）→ `render`（按版本渲染条号，导出 Word）

## 与方案文档（v2.1）的差异

这些是开工前确认过的修订：

1. `assess` 拆成 `assess`（纯规则）和 `explain`（模型），30 秒口径只算到 `assess` 结束。
2. 新增第五路召回 `recall_variant`：相邻两字互换、单字或整词重叠。单凭这一项标识相似程度最多为“中”。
3. 评估日和申请日分开：评估日决定适用的法律版本，申请日（或优先权日）决定在先关系。
4. 在先状态新增“已失效但可能仍被引证”：失效未满一年或失效日期不明的进入待核实（指南 18.3）；
   因连续三年不使用被撤销的、失效满一年的才判为不构成障碍。商标表相应增加失效日期、失效原因两个字段。
5. 依据按“在先状态 + 命中维度”选择：旧法下已注册或初审公告引第三十条、申请在先引第三十一条；新法引第二十条。
6. 商品关系先查区分表注释再看群组：注释明确不类似的（如 R10）判不类似；库里查不到的商品和开放式列举未列明的项目判待核实。
7. 历史交叉检索注释（H01–H09）只作提示，不参与定级。
8. 没有高 / 中风险候选时（包括没有召回、全部剔除），总结论由代码生成并引用“检索范围”这条全局事实，不要求依据。
9. 模型失败时，模板结论直接使用代码按映射表给出的依据，所以降级输出也能通过校验。
10. 包含关系：多出的部分全部由弱显著文字或商品通用名称组成时记为“高”（指南 5.5.1.12–14），否则为“中”。

## 已知限制

- 商标库目前只有仿真记录；真实记录到位后放进 `data/raw/real/` 重新建库即可。
- 页面是单进程 Streamlit：风险列表在规则阶段完成后即显示在执行过程里，但要等模型解释结束才能操作确认。
- 召回在内存里扫描候选池，适合初赛规模；数据量上万后需要改成走索引。
- 未做图形要素、驰名商标跨类保护。
- `MemorySaver` 只在进程内保存状态，重启会丢失进行中的任务。


## 评测（标识近似）

评测只检验“标识相似程度”，用官方已有的结论作标签，不靠我们自己标注：

| 评测集 | 来源 | 规模 | 用途 |
| --- | --- | --- | --- |
| `eval/guide_pairs.jsonl` | 《商标审查审理指南》5.5.1 节的中文官方例子 | 17 对 | 调参（公开材料，已看过） |
| `eval/tune_pairs.jsonl` | 驳回复审决定书中的商标对 | 83 对 / 25 个申请商标 | 调参 |
| `eval/frozen_pairs.jsonl` | 驳回复审决定书中的商标对 | 84 对 / 23 个申请商标 | 只报告指标，不看内容、不据此调参 |

决定书按申请商标整体划分，同一份文书的商标对不会同时出现在两边。“未认定”的引证不收。
文字清洗：去掉“及图”，只保留汉字；组合商标（带图形、外文）的结论可能部分取决于图形，所以另报“纯中文”子集。

当前结果（2026-11-17，冻结测试集，结果文件在 `eval/results/`）：

| 指标 | 改规则前 | 改规则后 |
| --- | --- | --- |
| 召回率（官方近似的对被判中或高） | 0.54 | 0.83 |
| 高风险命中率（官方近似的对被判高） | 0.14 | 0.52 |
| 反例正确率（官方不近似的对判低或不召回） | 1.00 | 0.94 |
| 反例被判高 | 0 | 0 |

局限：样本小且按文书扎堆；反例大多与申请商标没有共用汉字，区分难度低。比对前统一做繁简转换（opencc）。

## 规则依据（标识相似程度）

每类命中对应指南条目，写在 `app/rules/risk_table.py`。主要的校准：

- 仅带声调拼音相同记为“中”，读音相同且字形近似才记“高”（5.5.1.4，官方反例“好歌 / 好哥”）。
- 三字以上仅一字不同或仅多一字、首字相同记为“高”（5.5.1.7）；首字不同记为“中”。
- 完整包含对方且被包含部分占较长商标 40% 以上记为“高”（5.5.1.16）；占比小记为“中”。
- 两商标共有一段非弱显著的文字、各自另有文字，记为“中”（5.5.1.15）。
- 叠字、叠词记为“高”（5.5.1.3）；字序颠倒（含附加文字）单凭这一项最多到“中”（5.5.1.2 但书）。

已知的误判：指南里“北欧风情 / 北美风情”“大洋房 / 大洋”官方判不近似，系统判高。区别在含义，规则看不出来，
靠大模型在解释时标“建议复核”。


## 2026-11-18 更新

- **正式商标库**：国家知识产权局商标开放数据（第 29、30、32、43 类），通过 `app/library.py` 接入，检索索引见 `scripts/build_open_index.py`。
  产品中不再使用仿真数据；仿真记录只作为测试夹具保留在 `tests/fixtures/`。
- **在先状态**：开放数据没有法律状态，按公告日期推定，分档见 `app/rules/prior_status.py` 文件头。
- **按名称归组**：同名的多件注册归为一组；组按标识相似程度 > 命中通道数 > RRF 排序；解释和风险结论按组生成，Recall@10 按组统计。
- **大模型调用上限**：每次评估最多为 `LLM_MAX_GROUPS`（默认 10）个名称组调用大模型，其余用模板。
- **驳回复审**：页面上切换到“驳回复审逐项比对”，录入引证编号和实际申请日，逐件比对、每件都有结论；不做复审论证提纲。
- **相关案例**：报告附录列出案例库中文字相近的决定书，仅供参考，不作为依据。
