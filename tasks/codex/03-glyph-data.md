# 任务 03：调研并选定汉字部件拆分数据

先读 [README.md](README.md) 里的通用规则。

## 背景

系统要判断两个汉字是否“形近”（如 己/已、茶/荼、沐/沭）。现在用的是一份人工起草的 75 对字表 `data/glyph_pairs.csv`，覆盖面小，也没有可靠出处。

我们打算改成用公开数据自动计算：把每个汉字拆成部件和结构（例如“沐 = 左右结构，氵 + 木”），部件和结构相同或只差一笔的判为形近。这个任务只负责**找数据、评估、下载**，计算方法我们自己写。

## 要做什么

1. 调研可用的公开数据，至少比较 3 个候选。方向包括但不限于：
   - 表意文字描述序列（IDS）数据，例如 CHISE、cjkvi-ids 等项目；
   - 四角号码、笔画序列等编码数据；
   - 已有的中文形近字数据集。
2. 对每个候选，核实并记录：
   - 来源网址、维护者、最近更新时间；
   - **许可协议原文名称**（如 GPL-2.0、CC BY-SA 4.0），是否允许我们在一个比赛项目里使用和分发；
   - 覆盖范围：能覆盖《通用规范汉字表》8105 字中的多少（请实际统计，不要引用别人的说法）；
   - 数据格式，并给出 5 个示例字的原始数据行（沐、沭、茶、荼、己）。
3. 推荐一个作为主数据，最多再选一个作为补充，说明理由。
4. 把选中的数据文件下载到 `collected/glyph/`，**连同它的许可文件**一起放进去。许可不允许分发的，只下载不提交，在报告里写清楚。

## 不要做

- 不要写形近判断算法，不要改 `data/glyph_pairs.csv`。
- 不要使用来源不明、没有许可说明的数据。

## 交付

- `collected/glyph/`：选中的数据文件和许可文件
- `collected/glyph/REPORT.md`：候选对比表（来源、许可、覆盖率、格式、优缺点）、推荐结论、5 个示例字的原始数据、覆盖率的统计方法
